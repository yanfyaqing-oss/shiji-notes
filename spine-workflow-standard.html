Production Standard

Spine角色制作与
Unity交付规范 v1.0

适用于个人练习、团队协作和作品集项目。进入公司项目后，以项目组已有规范为最高优先级；没有既定规范时，使用本页作为默认标准。

一套命名

小写英文、下划线、两位编号；左右以角色自身为准。

一个角色工程

同一Skeleton包含idle、run、attack、hit和die等全部动画。

一条稳定交付链

源工程可带版本号，Unity导出文件名长期保持稳定。

六条必须遵守的规则

01 · 命名全部使用小写英文和下划线，不用中文、空格和临时名。
02 · 角色一个角色、一套SkeletonData、多个Animation，不按动作拆工程。
03 · 原点root位于脚底基准，普通idle、run、attack默认原地制作。
04 · 引用动画、事件、挂点接入Unity后，不得无通知改名或删除。
05 · 导出Unity文件名保持稳定，更新时覆盖同名文件并保留.meta。
06 · 交付每次说明Spine版本、改动内容、事件、挂点和破坏性修改。
01 · 通用命名规则

统一使用 lower_snake_case。编号使用两位数；左右以角色自身方向为准。

类别推荐避免
骨骼upper_arm_l、hair_back_02Bone01、左手、NewBone
动画idle、attack_01Attack1最终版、idle 新
事件evt_hit、evt_footstep_levent1、这里出特效
挂点socket_weapon、socket_hitpoint1、武器点
 
_l = 角色左侧
_r = 角色右侧
01 / 02 / 03 = 统一两位编号
02 · 工程、版本与目录 
hero/
├─ spine/      hero_v001.spine
├─ images/     body / face / hair / clothes / weapon
├─ export/     hero.json / hero.atlas.txt / hero.png
├─ preview/    idle与攻击预览
└─ notes/      hero_changelog.txt

源工程可以递增版本：hero_v001.spine、hero_v002.spine。Unity导出名始终保持hero，不要使用hero_final_2。

更新Unity资源时覆盖json、atlas.txt和png三个同名文件，不删除Unity生成的.meta、Atlas Asset、Material和SkeletonData Asset。

03 · Skeleton与Bone

推荐基础结构

root
└─ pelvis
   ├─ spine_01 → spine_02 → neck → head
   ├─ upper_arm_l → forearm_l → hand_l
   ├─ upper_arm_r → forearm_r → hand_r
   ├─ thigh_l → shin_l → foot_l
   └─ thigh_r → shin_r → foot_r

Root基准

root position = 0, 0
root rotation = 0
root scale = 1, 1
脚底基准 = Y 0

呼吸、摆动等局部变化不要直接用root完成。默认制作原地动画，角色在游戏世界中的位移交给Unity控制。

软性部件

hair_front_01、hair_back_02、coat_l_01、skirt_back_01。规则为“部位 + 方向 + 顺序”。

04 · Slot、Attachment与Skin

Slot

slot_head、slot_eye_l_pupil、slot_torso、slot_weapon。名称描述容器用途和绘制层级。

Attachment与图片

head、upper_arm_l、hair_front_01、weapon_sword_01。图片文件名尽量与Attachment一致。

Skin

default、outfit_casual_01、outfit_armor_01、weapon_sword_01。需要自由组合时，按body、hair、outfit和weapon分类。

05 · 挂点、事件与约束

Unity挂点

socket_weapon      武器与刀光
socket_hit         命中特效
socket_projectile  弹道起点
socket_body        护盾与身体特效
socket_foot_l/r    脚步灰尘

Spine Event

evt_hit
evt_slash_start / evt_slash_end
evt_footstep_l / evt_footstep_r
evt_projectile
evt_skill_release
evt_camera_shake

事件应放在画面真实发生的时刻。命中、发射和脚步时机由动画师给出，不能让程序凭感觉猜。

约束

ik_leg_l、ik_arm_r、tc_weapon、path_hair_01。只在确实提升稳定性和效率时使用。

06 · 动画命名与制作 
idle / walk / run
jump_start / jump_loop / jump_end
attack_01 / attack_02 / attack_heavy
hit_front / hit_back / hit_air
die / revive
skill_01 / skill_02 / ultimate
  • 没有项目要求时使用30 FPS，项目确定后不要随意改变。
  • 只给实际变化的骨骼和属性打关键帧，不给每个动画的全身无差别打Key。
  • 循环动画检查首尾、重心、脚滑、头发和衣物断点。
  • 攻击拆成前摇、出手、命中、收招，并确保可返回idle或衔接下一段。
  • 分别以0.5、1、2倍速度检查节奏和穿帮。
07 · 拆图、Mesh与权重
  • 关节处保留足够覆盖，极限旋转时不能露出空洞。
  • 绑定前测试抬臂、交叉、最大迈步、弯腰和转头等极限姿势。
  • 脸、躯干、裙摆、披风和头发可使用Mesh；武器、护甲片等刚体不做无意义高密网格。
  • 顶点只加在需要变形的位置，单顶点尽量由2～4根骨骼影响。
  • 检查权重过渡、轮廓塌陷、拉裂、穿帮和无效顶点。

够用的最少顶点，比无意义的高密度网格更专业，也更利于移动端性能。

09 · Unity资源与替换流程 
Assets/SpineAssets/Characters/
├─ Xiaoren_Test/  xiaoren三件套
└─ Hero/          hero三件套

同一角色更新动作或贴图：覆盖三件套，保留meta和生成资源。完全不同的正式角色：新建目录、新生成SkeletonData和Prefab，不直接覆盖测试骨架。

PlayerRoot
├─ 移动、碰撞、状态脚本
└─ Visual
   └─ SkeletonAnimation

正式项目把游戏逻辑与视觉对象分开，更换角色时只替换Visual。

10 · 动画与交付验收
  • 动作轮廓一眼可读，武器方向清楚
  • 支撑脚与重心合理，没有漂浮
  • 关键动作有快慢、停顿和命中感
  • 网格、权重、衣物和关节无穿帮
  • 循环首尾连续，Run没有脚滑
  • 攻击可返回Idle或衔接下一段
  • 动画、Event和socket名称正确
  • Atlas、透明边缘和材质正常
  • Unity中0.5/1/2倍速测试通过
  • Console保持0 Error

交付说明模板

角色：hero
Spine：4.2.43
日期：YYYY-MM-DD

新增：run、attack_01
修改：idle头发摆动、hand_r权重
事件：attack_01新增evt_hit
挂点：新增socket_weapon
注意：已重新打包Atlas，需覆盖三件套

改骨骼名、动画名、Slot、Event或挂点属于破坏性修改，必须主动说明。

11 · 禁止事项与当前执行
  • 不用中文、空格、Bone01、Slot01和“最终版2”等命名。
  • 不为每个动作建立一个独立Spine角色工程。
  • 不让普通Run的root持续向前移动。
  • 不为所有骨骼无差别打关键帧。
  • 不混用PMA与Straight Alpha设置。
  • 不只交付JSON而遗漏Atlas或PNG。

当前xiaoren是已有测试素材，原有B_等旧命名不用强行重做。从新增内容开始使用：

动画：idle / run / attack_01 / hit_front / die
事件：evt_hit / evt_footstep_l / evt_footstep_r
挂点：socket_weapon / socket_hit / socket_body
